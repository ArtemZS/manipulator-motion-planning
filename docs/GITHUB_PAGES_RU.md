# Автоматическое обновление GitHub Pages

Публичная галерея: https://artemzs.github.io/manipulator-motion-planning/showcase/index.html

Сайт собирает и публикует workflow `.github/workflows/pages.yml`. Источник Pages
в настройках репозитория — **GitHub Actions**. Ветка `gh-pages` больше не участвует
в обновлении; её прежний снимок можно оставить в истории.

Автопубликация запускается после push в основную ветку при изменениях сцен,
численных входов галереи, статистики, кода, зависимостей или самого workflow.
Сейчас основная ветка — `codex/scenes-and-pareto-views`. При смене основной ветки
условие workflow использует новую настройку репозитория; также разрешите новую
ветку в настройках среды `github-pages` (Deployment branches).

## Как обновлять результаты

Расчёты RRT* → B-сплайны → NSGA-II и серии по seed выполняются локально.
`results/` остаётся в игноре: GitHub не имеет доступа к файлам на компьютере.

1. Обновите локальную галерею `results/showcase/` и общий отчёт `docs/experiments/`.
2. Выполните `just pages-snapshot`. Команда переносит в `docs/showcase/` только
   параметры, траектории и отчёты демонстрационных запусков. Если галерея лежит
   в другом месте, передайте её каталог: `just pages-snapshot results/другая_галерея`.
3. Закоммитьте изменения `docs/showcase/`, `docs/experiments/` и конфигураций сцен,
   затем сделайте обычный push в основную ветку.

Ручной перенос HTML, GIF или файлов в `gh-pages` не требуется. Презентации
и текст выступления из `docs/presentation/` остаются в игноре.

## Что делает Actions

- Устанавливает Python 3.14 и зависимости из `uv.lock`, проверяет код и тесты.
- Повторно проверяет сохранённые сплайны и строит анимации с исходными seed
  и ракурсами, четыре траектории, таблицы и графики Парето.
- Формирует статистические разделы всех сцен из единого `docs/experiments/`;
  численные итоги и исходная выборка не пересчитываются.
- Проверяет локальные ссылки и публикует готовый статический сайт напрямую
  через артефакт GitHub Pages. Дополнительные токены или секреты не нужны.

Если геометрия в `configs/` или ресурсах пакета отличается от сохранённого
расчёта, сборка завершается ошибкой с указанием сцены. Сначала пересчитайте сцену
локально, обновите отчёт и выполните `just pages-snapshot`. Это предотвращает
публикацию старой траектории под новым описанием препятствий. При любой ошибке
сборки существующая опубликованная версия сайта продолжает работать.

Статус и журнал: https://github.com/ArtemZS/manipulator-motion-planning/actions/workflows/pages.yml
Повторный запуск без изменений: **Actions → Обновление showcase на GitHub Pages → Run workflow**.

## Проверка локально

```powershell
just pages-build .cache/pages-check
```

Сборка использует только отслеживаемые входы `docs/showcase/` и общую сводку.
Выходной каталог и соседний каталог с суффиксом `-work` должны быть пустыми.
Для быстрой проверки можно уменьшить число кадров:

```powershell
uv run python scripts/build_pages.py build --output .cache/pages-check-short --frames 7
```

Исходный экспорт уже готовой локальной галереи по-прежнему доступен через
`just pages-export`. Опубликованный `build-info.json` содержит SHA исходного
коммита, ID запуска Actions, список сцен и число статистических пар.

Локальная галерея после `just serve`: http://127.0.0.1:8766/showcase/index.html
